## 工程与验证方法

- 先补关键行为回归，再调整呈现；沿用现有 Node、Vitest、Playwright 与 Django 隔离集成启动器，不引入第二套测试框架或生产依赖。
- PC 与小程序各自复用现有组件与原生能力，不跨端共享 DOM/Vue 组件，不将权限、报价或商品保存重新包装为另一套业务框架。
- 视觉证据与自动测试分开记录；Mock HTTP、真实隔离数据库、微信模拟器和真机也分别记录。
- 人工体验仅使用启动器创建的唯一临时数据库和私有临时媒体目录；支付方式及外部凭据关闭。正常退出或 SIGTERM 后沿用原清理流程，仅停止自有进程并删除本轮数据库。
- 代表页面完成后先提交中途验收；用户现已明确验收并授权推广。合入主分支、推送与上线仍另行执行。

## 切片工程复核

1. **职责与契约**：PC 框架负责导航展示；商品域负责编辑状态；mini 购买页面负责局部呈现。无 API、权限码和数据库契约变更。
2. **数据库约束**：继续使用既有 SKU 标识、修订检查、库存事务与订单幂等；视觉层不另建业务事实。
3. **重复与失败**：保持原保存/上传并发保护；重选规格确认时检查原行快照并单次写入；提交结果不明保留同一请求键；库存明确拒绝后获取真实报价，用户确认调整后再次报价，不自动下单。
4. **规模**：列表仍用既有分页、批量及服务端查询；不为本次视觉在客户端拉取全部商品或新增逐行库存请求。库存明细继续从原库存模块进入。
5. **证据**：见上表；自动、隔离数据库、人工浏览器、模拟器分别记录，真机与真实平台留待独立验收。
6. **扩展位置**：下一批页面沿现有业务域及公共 HTTP 入口扩展。导航项只维护展示分组，权限读取原路由元数据；不复制第二份权限映射。
7. **复用与例外**：复用 Element Plus、原商品表单、媒体/规格编辑器、持久操作控制器及 mini cart/session/orders/storefront-shell。新增样式文件只集中本轮视觉变量与应用框架；商品重选状态留在详情页，不提前抽象万能业务组件。
