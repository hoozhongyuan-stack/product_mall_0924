## 配置责任

PC「店铺与小程序 → 小程序接入」管理本商城使用的小程序 AppID 与 AppSecret。服务端负责加密、有效配置读取和微信凭据校验；小程序客户端只使用 wx.login 返回的临时 code，不持有 AppSecret。既有环境变量继续用于尚未托管的部署；首次托管后不在解密失败时退回旧环境凭据。

配置保存、凭据校验、真实微信登录和真机验收是四个独立状态。凭据校验成功不表示支付、订阅消息或代码发布已验收，也不会开放这些通道。

- Secret 只允许保留或替换，不回显原文、尾号、密文或平台 token，不写入浏览器持久存储。
- 保存和校验均需独立权限及当前账号密码二次确认，绑定配置修订号。
- 写入冲突与网络结果未知时先重新读取核对，不自动重发 Secret。
- 已有会员身份约束 AppID 变更；更换小程序主体需要独立的数据迁移方案。
- 已保存凭据的校验调用微信普通模式 stable_token，显式 force_refresh=false；不强制轮换、不自动重试、不回退旧 token 接口。平台可能要求管理员确认。只返回归一化状态，丢弃 token。

微信请求契约根据[官方 stable_token 文档](https://developers.weixin.qq.com/miniprogram/dev/server/API/mp-access-token/api_getstableaccesstoken.html)核对；真实账号的权限、IP 白名单与平台结果仍以目标环境验证为准。

## 部署与凭据交接

加密密钥属于部署配置，与 Django SECRET_KEY 分开保管。所有应用实例使用同一持久密钥；数据库密文与加密密钥分别备份。数据库备份不能替代密钥备份，不能在升级时重新生成密钥。

复用 E5 容器、发布修订检查、备份恢复脚本，先修复 Linux 服务 UID 读取秘密文件的问题。应用容器以非 root UID 10001 运行；秘密文件由部署人员安全安装，升级脚本在停止旧服务前完成实际用户读取预检。配置检查不得迁移数据库、调用微信或变更凭据。

目标 UAT 使用用户提供的阿里云服务器与 `https://uat.aition.xin/`。服务器已有三组 Compose 服务，商城应使用独立项目、数据库、持久卷和端口，并在配置校验后追加专用域名反向代理。禁止全局清理镜像、卷或停止其他项目。实际资源限制、域名证书、部署修订及运行证据在部署后补充。

后台可用后，AppSecret 由用户直接录入并提交，不通过聊天或 Git 交接。管理员登录凭据仅通过本机私密文件交接。小程序体验包的 AppID、HTTPS API 地址与后台有效 AppID 必须一致；真机验收不关闭合法域名或证书校验。

后端全量回归 803/803（324.419 秒）通过，综合覆盖率 87%；精确查询确认本轮专用数据库已清理。定向回归 125/125 包含 PostgreSQL 双线程验证首次会员登录与配置保存的两种顺序。迁移一致性检查无变化。

1. **归属与契约：** `wechat_integration` 负责配置与校验；身份仍归 `customers`，公共读取返回不可变快照，接口见 5.31 节。
2. **数据库约束：** 单例主键与修订号；首次登录及保存共享单例行锁，会员身份锚点阻止不兼容的 AppID 切换。
3. **重试与失败：** 密码确认、修订冲突与快照复核共同保护写入；请求结果未知必须重读；托管密文损坏或部署 key 缺失时拒绝使用，绝不回退旧环境凭据。
4. **规模：** 配置为单例；会员身份只读取至多两个不同 AppID，不返回成员明细；读取、保存及平台校验各有配额，平台响应有体积与时限约束。
5. **证据：** 上述本地测试覆盖允许/拒绝、并发和故障；平台、部署、真实登录及真机仍保持独立待验收状态。
6. **扩展点：** 平台校验适配放 `probe.py`，配置安全与快照放 `credentials.py`，各业务规则保持原所属域；不引入跨域通用仓储或新状态库。
7. **复用与视觉：** 对应样板 70 平台凭据配置的本次小程序接入范围，沿用现有「店铺与小程序」导航、Element Plus、设计变量、公共 API 和确认协议，按统一页面状态与桌面/窄屏规则检查；未扩展到支付、消息与提审发布。
