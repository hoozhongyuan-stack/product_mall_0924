# 订单履约治理实施与验收

业务依据：根目录《B2C商城小程序V1.0需求文档》的“订单履约治理：已确认开发增量（2026-10-12）”和已确认的三端 HTML。接口字段见 `contract-v1.md` 的同名增量。

## 三端行为

| 场景 | 操作端 | 库存／权益 | 顾客详情 |
| --- | --- | --- | --- |
| 配送到家 | 指定前置仓备货、开始配送、失败登记、重试、完成 | 对应前置仓库存；按实际数量交付 | 履约仓、配送状态、异常与分项交付进度 |
| 自提 | 指定前置仓备货、核对提货码、确认实际交接 | 对应前置仓库存 | 自提地址、提货码、待提及已提数量 |
| 快递 | 平台后台按可发数量分批发货 | 平台总仓库存 | 批次物流、已发和未发数量、确认当前批次收货 |
| 虚拟商品 | 仅平台／指定前置仓／两端共同，由成交范围决定 | 同一凭证共享权益余量和修订 | 可核销范围、已用、冻结、可用数量及实际核销方 |

平台查看本地履约订单，但备货、配送、提货操作在前置仓中心。前置仓工作台没有平台快递发货能力。商品范围变更不会改写成交订单的范围；服务端验证员工、权限、凭证、数量、修订、请求身份和成交授权。

下单暂占库存，可信付款扣销售库存；交付和核销不会再次扣销售库存。售后冻结只影响对应数量，剩余可交付数量继续履约。未交付退款回原仓；已交付退货经验收后按实际可售数量回原仓；已用权益退款不恢复次数。订单完成按有效义务和售后事实判断，不把已退货数量重复计入未交付义务。

## 本地预览

启动：在 `pc-admin` 执行 `python3 scripts/run-browser-integration.py --fulfillment-preview`。脚本创建独立随机 PostgreSQL 数据库、临时管理账号及八个合成订单，启动实际 Vue 后台、Django API 和小程序源码浏览器预览。当前地址与临时账号保存在脚本输出的私有 `preview-access.json` 中。

八个初始场景：配送、自提、快递、仅平台权益、仅指定仓权益、共用权益、快递加共用权益混单、部分退款冻结配送。实际联动验收在此前的独立数据集中完成。最终用户预览重新生成了八个未操作的订单，供用户从初始状态体验。

浏览器预览加载实际小程序 Page JavaScript、WXML 和 WXSS，并请求同一隔离 Django API。页面提供前置仓／顾客视角切换。预览桥仅监听本机，校验 Host、写入 Origin、请求长度及资源路径；未知结果先查询实际请求记录，成功后恢复页面，否则沿原请求身份重放。

停止该脚本时只清理其创建的数据库、自有服务和临时文件。支付、物流外部渠道保持关闭。上述本地验收阶段没有推送、UAT部署或线上发布。

## 数据迁移边界

旧订单、交付和核销历史保持原事实。旧前置仓快递订单不会自动迁移库存、资金或改写履约仓；新订单禁止该路由。旧无范围快照的权益按仅平台解释。历史空 digest 核销记录保留；新核销强制规范请求摘要并禁止复用任何历史已占请求键。

本次包含履约数据库守卫，部分守卫迁移不提供自动反向恢复。后续部署须备份并按实际数据执行迁移验收；本地迁移通过不代表已经部署。
