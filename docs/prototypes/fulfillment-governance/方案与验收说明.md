# 订单履约治理 · HTML 评审说明

日期：2026-10-12。阶段：用户已认可方案，HTML 交互稿待确认。业务开发尚未启动。

## 打开方式

- 本地预览：<http://127.0.0.1:8872>。
- 单文件：`订单履约治理交互稿.html`，可直接在浏览器打开，无外部字体、脚本、图片或业务服务依赖。
- 源文件：`index.html`、`styles.css` 和各 `.mjs` 模块；`npm run build` 生成单文件。

顶部切换平台后台、前置仓中心和顾客订单详情。三端使用同一份内存模拟订单；本页操作联动，刷新或“重置演示”恢复初始值。手机内容区独立滚动；外围选择器、库存观察和状态控件是评审工具。

## 评审范围

平台：统一订单、筛选及分页、订单详情、快递发货、授权虚拟核销、未交付或未核销退款、售后驳回、商品核销范围配置与新订单快照对照。

前置仓：切换已授权仓、履约待办、本仓订单详情、备货、配送、异常记录与继续配送、自提凭证核验、授权虚拟核销。平台快递不进入本仓实物待办；混合订单只在本仓显示授权权益操作。

顾客：实物交付进度、快递运单、自提凭证、虚拟剩余权益及有效期、分项履约记录、未交付或未核销售后、快递确认收货。代码凭证为不可用于真实业务的演示码。

## 推荐体验顺序

1. 平台打开配送订单，查看履约方和扣库仓；切前置仓操作备货、配送、送达，再切顾客查看结果。
2. 顾客选择自提订单查看演示码；切前置仓输入错误码后改为正确码，完成提货。
3. 平台对快递订单登记公司和运单；顾客确认收货，检查前置仓没有该订单的发货任务。
4. 顾客查看洗车次卡码；平台核销2次后切前置仓，检查剩余2次，再核销完成。
5. 顾客对配送2件申请1件售后；前置仓交付另1件，订单等待剩余售后关闭；平台退款后检查仅回补原仓1件。
6. 顾客对混合单申请1次服务售后；平台仍能发礼盒，顾客收货后仍等待权益处理；退款并完成剩余核销后整单结束。
7. 平台配置核销范围为南山仓并保存，生成演示新单；原有洗车订单仍保留深圳仓范围，新单使用南山仓范围。
8. 通过评审状态控件查看加载、空列表、读取失败及无权限；无权限状态不展示业务订单与库存辅助信息。

普通销售、餐饮联盟、积分兑换、混合、未付款、到期权益和售后冻结均有示例。实物部分冻结后只交付非冻结剩余量；若已交付部分且售后驳回，释放部分重新进入备货。混合单服务售后不阻断独立实物交付。
