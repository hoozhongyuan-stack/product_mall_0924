## 实现与兼容性

| 能力 | 实现及边界 |
| --- | --- |
| 商品图文 | 新建、编辑复用 catalog 域 `ProductDescriptionEditor`。Tiptap 3.31.3 必要模块精确锁定；支持正文、标题、粗斜体、列表、撤销重做、素材图片、图片说明/顺序和手机宽度预览。沿用 `descriptionHtml`，保留父表单修订冲突与未保存保护。 |
| 图文图片 | 从现有素材库取得素材 ID，服务端忽略传入 src，只生成固定的授权访问地址。最多 20 个图片节点、说明 200 字符、规范 HTML 20000 字符。小程序复用 API 根地址转换图片路径并限制图片宽度。 |
| 素材引用 | `ProductDescriptionImage` 外键关系加入现有素材引用、删除保护、孤儿清理及公开读取逻辑。与商品修订同事务更新，并对新旧素材按固定顺序加锁。 |
| 库存布局 | 六个入口复用全站 secondary-nav；移除重复大标题和自绘 tabs。`/inventory` 仍是库存查询，另有 warehouses、inbounds、outbounds、stocktakes、ledgers 子路由。 |
| 入出库选品 | 复用 Element Plus dialog/table/pagination；显示主图、名称、规格、商品编号、SKU、换算和所选仓库账面/锁定/可售量。支持搜索和分页，禁止同单重复 SKU；换仓后重新读库存。 |
| 库存接口 | `/inventory/skus` 保留原分页与权限，追加展示字段及可选 warehouseId。规格和余额批量读取；不暴露价格，不扩大通用素材库权限。契约见 `contract-v1.md`。 |
| 店铺/小程序 | 拆为两个主菜单分组，复用原路由和权限。店铺下保留装修、素材等运营入口；小程序下为接入、订阅消息、消息任务与代码版本。 |
| 批量上传 | 共用 `AssetUploadQueue`，复用原单文件上传 API 与服务端检查，每批最多 20 个，串行上传。素材中心与素材选择弹窗共用同一实现。 |

库存的草稿、确认、数量换算、单位版本、库存重验、幂等与事务服务保持原有语义。选品界面库存仅作填写参考，确认单据时仍以服务端最新状态为准。详情中的图片使用商品主图，不新增 SKU 独立图片模型。

## 上传结果与离页规则

- 每个文件独立显示等待、上传中、成功、校验失败、明确失败、结果待确认。
- 成功文件不会随部分失败被撤销；手动重试只适用于明确失败的文件。
- 网络异常、5xx、408 不能证明服务器没有保存，标为“结果待确认”，停止后续自动派发，要求先查素材列表；不自动重传。
- 401、403、429 暂停后续派发。账号/权限变化和组件卸载使旧响应失效。
- 停止上传只停止后续文件；在途请求仍可能在服务器完成。关闭弹窗、路由离开、同组件路由更新和浏览器关闭均有对应保护。
- 只有实际生效的路由更新才销毁素材弹窗；取消导航或被后续 guard 拒绝时保留当前队列。

## 用户中途验收建议

1. 商品管理打开示例草稿，检查工具栏、图片说明与手机宽度预览是否符合编辑习惯。
2. 库存检查六个入口的位置与其他页面是否一致；在出入库草稿按名称、规格或 SKU 查找商品，确认信息足以区分不同规格。
3. 店铺/小程序分别检查其二级菜单归属。
4. 素材中心一次选多张图片，观察逐文件结果和成功记录；在等待状态切页时检查保留/离开提示。

确认代表页后再推广盘点等剩余选择器并安排 UAT 发布。部署需先应用新增 catalog 0009 迁移；数据库关系为加法变更，旧商品文字内容无需迁移。真实小程序图片展示、登录与 iPhone/Android 验收仍需目标环境和设备证据。


## 2026-10-09：多单位规格自动库存关系

用户确认：单位本身是规格值，商品开启换算后由系统自动确定库存关系；运营不选择“共享／独立”，不手工绑定。本节取代历史人工绑定流程，产品规则唯一来源仍为工作区需求文档第 4.9 节。

### 实现边界与七项评审

1. 商品域负责单位规格配置、校验和 SKU 派生单位；库存域通过 `pool_access` 自动建立实物关系。创建与规格 preview/save 的 `unitConversion` 字段见 API 契约，不新增库存事实系统。
2. 沿用商品／规格组合唯一约束、SKU 单位版本正整数约束、池成员唯一映射、余额与不可变流水约束；新增 Product 可空单位配置。有效轴／值归属、基本单位为 1、基本 SKU 完整性和 1—1000000000 比例范围在事务边界校验。
3. 沿用商品及 SKU 修订、预览签名与原子保存；Product → SKU 锁顺序与旧单位写口一致。单据草稿或任一组成员已有余额／交易／库存历史后拒绝改变库存关系和换算含义；只改价格保留已有库存。新输入或修改会清空旧预览，确认等待中重验配置快照。
4. 复用既有最多 2 轴、20 值、100 SKU 上限。单位轴也占一轴；本次不扩大数据规模或改动库存分页。库存查询仍每仓库、每份实物余额仅统计一次。
5. 测试覆盖创建派生单位、不同非单位组合分离、无历史编辑／删除／关闭配置、保留 SKU 身份、已有引用拒绝变更、伪造单位和异常键拒绝、公开可售换算及混合购物车超售拒绝。真实隔离数据库浏览器覆盖单位配置修改／预览／保存／刷新回读，桌面和 390 px 各一套；实际结果补充于下。
6. 将来扩展单位或规格限额时修改商品单位配置入口及库存域自动归组入口，不新增另一套余额、价格或锁库服务。装配／拆解、历史余额迁移、本轮不实现。
7. 新建和编辑复用 `UnitConversionEditor`、`SkuTable`、已有确认组件与设计变量。普通商品使用一个单位输入；多单位 SKU 只读显示派生换算关系。移除独立库存池绑定组件及其菜单面板；公开人工绑定写口退役。已有旧测试数据不自动合并、删除或重置。
