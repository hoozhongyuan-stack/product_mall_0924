# 后台列表管理页统一规范与覆盖矩阵

更新日期：2026-10-11。依据：已确认的 `../后台列表规范原型/PRODUCT.md`、`SURFACE.md`、`DESIGN.md`，当前 `pc-admin/src/navigation.ts`、路由和业务组件源码。本文件记录实施范围与分阶段验证证据。发布状态以文末的 UAT 发布记录为准，不能从本地验证推定 UAT、微信平台或生产业务验收。

## 统计口径

后台导航共 41 个入口，其中 27 个是列表管理入口，14 个是概览、配置或单笔业务操作。27 个入口展开为 31 个独立列表分区：商品入口包含 SPU、SKU 工作区、分类三张列表；餐饮财务包含提现和佣金两张；代码版本包含版本和同步记录两张。再加上隐藏导航、保留深链的历史餐饮进货价档案，共 **32 张主列表**。

详情中的流水、人员、桌台和版本历史等是附属表，单独说明，不重复计入主入口。商品规格成本在编辑弹窗内，不作为第 33 张主列表。

## 统一交互与组件

- 列表顺序为标题与新增入口、检索区、已选工具栏、表格、分页。检索提供查询与重置，字段按业务实际提供；空、加载、无结果、读取失败和重试保留明确反馈。
- 当前页勾选与全选只覆盖已加载的当前页。查询、重置、翻页、每页条数改变或身份/权限改变后清空勾选；不把未加载记录算入批量操作。
- `AdminListPager.vue` 使用真实总数，中文分页，20/50/100 条、页码与跳页；改变条数回第一页。服务端分页列表继续调用真实分页接口。账号、权限组、仓库和分类只有在接口返回完整授权数组时使用前端分页。
- `AdminCursorPager.vue` 用于日志、消息任务、代码版本和同步记录，保留服务端签名游标，20/50/100 条、上一页与下一页。显示的页数只是已走过的游标页序，不展示虚构总数，也不提供任意跳页。
- `AdminSelectionBar.vue` 统一已选数量、清空与批量入口。`AdminSelectedRowsDialog.vue` 只读对比当前所选记录，不调用业务写接口，不能将其描述为批量审核、批量发放或批量修改。
- 行查看、编辑、新建、状态改变和批量操作使用真实组件的弹窗或确认框；保留原详情路由以支持已有深链和刷新恢复。嵌入组件不使用 iframe。异步离开确认使用 `before-close`，只有允许离开后才关闭；提交中和结果未知的原操作身份、幂等键、修订冲突与恢复入口继续保留。
- `AdminStatusBadge.vue` 统一状态含义：绿色为成功/有效，蓝色为处理中，橙色为待处理/待核查，红色为失败/异常/驳回，灰色为草稿/关闭/停用。颜色辅助文字，不能独立承载状态。财务“审核通过”仍表示待打款，不显示为已支付成功。
- 普通行操作使用蓝色，删除、停用、驳回等危险操作使用红色；主操作继续使用品牌主色。`styles/lists.css` 与 `styles/dialogs.css` 统一表头、行间距、容器、弹窗滚动与窄屏适配。原生表格有操作列时固定末列；无操作表使用 `admin-list-no-actions`。

## 附属详情表与边界

前置仓账户详情内的收入/提现历史已有独立服务端检索、20/50/100 分页、勾选只读对比和单笔审核/付款登记弹窗。餐饮店详情内桌台/人员表已接入检索、统一分页和本域编辑弹窗；桌码勾选与下载仍限定原管理权限及启用桌，不增加只读账号的桌码授权。前置仓详情人员表本轮仅统一授权操作弹窗，保留原人员列表能力。餐桌批量创建保留“先校验与预览”，不与主列表批量启停混为一项。

会员详情内积分流水与消费/等级流水目前保留原固定 20 条前后页，没有本轮统一检索、勾选与条数切换；优惠券发放记录、页面发布历史和代码上传/审核历史也属于业务详情附属表，不以主列表覆盖矩阵宣称全部统一。若后续将“所有管理页”扩展为每个详情内部的所有历史表，需要单独确定适用检索与只读批量动作，避免为了统一样式添加积分、资金或发布批量写。

代码版本“内部存储状态”来自服务端实际包状态，当前未提供按此状态的数据库筛选；版本关键词与同步状态筛选均由服务端执行，不能将当前页筛选伪装为全历史检索。历史档案和余额/佣金只读表所有信息可直接展示，不强造编辑或资金操作。
