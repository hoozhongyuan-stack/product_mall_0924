# 后台图片、导航反馈与加载状态修复

更新日期：2026-10-12。范围：用户确认的列表图片拖慢切页、子菜单点击缺少反馈、读取期间出现错误业务结论。源码、自动化测试、本地浏览器及 UAT 发布分别记录，不把部署就绪视为用户业务验收通过。

## 浏览器问题基线

在 UAT 主账号下实际点击10个模块、41个导航入口及商品分类标签。商品分类两次请求分别约6.15秒和7.28秒；其他分类读取曾为0.12–0.23秒。独立微页面列表约6.68秒。底部导航页面脚本约6.26秒，后续草稿读取约5.28秒；素材请求进行时，客服/小程序页面脚本等待约8–9秒。以上是单次请求记录，不是平均时延。

列表的小图片实际请求1.7–2.4MB原素材，私有响应禁止缓存；图片传输期间，页面脚本和JSON请求也明显等待。代码版本页还曾在读取完成前显示密钥未配置、随后变为已配置。此次浏览器没有观察到永久失效，但旧内容停留、按钮禁用及错误中间状态共同造成“菜单不能用”的体验。

## 实现边界

1. **小图与原图分开**：IMAGE/GIF列表输出静态JPEG，GIF仅首帧，最长边320px、最大64KiB。商品SPU、库存SKU、积分商品、素材列表与选择卡、自动页面编辑画布及组件小预览使用thumbnailUrl；原素材仍用于用户主动预览、真正商品编辑、手动页面预览及热区绘制。视频列表不预读视频，用户打开预览后才读取。缩略失败仅占位，不禁用READY素材选择，不回退下载原大图。
2. **原权限继续执行**：管理员与公开缩略接口分别复用原文件完整权限及当前公开可见规则，生成结束后再次核验会话、权限/公开引用和源状态。缓存是私有派生文件，不提供公开目录；响应继续no-store。不同源版本隔离，原子发布、删除后清理；不修改原素材或业务记录，不新增迁移或生产依赖。
3. **资源有界**：沿用现有ffmpeg，输入最多10MiB、沿用尺寸/像素校验，单线程、8秒解码截止、64MiB单次分配上限、全媒体卷最多两个并行生成槽。单次分配上限不等同总进程内存保证。缓存v2保留完整指纹，图片相对路径95字节，符合E5原有98字节限制。升级与定时备份先停止写入者，再通过受控命令全树校验并清理v1派生缓存；不改变原素材、业务数据或备份校验。繁忙返回受控503；可用`warm_asset_thumbnails --limit 50`预热旧素材，参数最大200。
4. **切页立即反馈**：应用主、移动、二级与面包屑导航显示目标名称和进度；3秒后提示慢加载及重试。原链接修饰键与新标签行为保留。完成、取消、拒绝、会话失效正确清理，旧请求不能覆盖新的菜单选择。
5. **失败可安全恢复**：保留普通重试。浏览器可能缓存首次失败的模块，因此提供显式“安全刷新并重试”：先导航到概览执行原离开守卫，通过后复核最新请求、登录、权限及同源目标，才刷新到原目标。取消离开、操作结果未知或身份/权限变化时不刷新。没有自动强制刷新。
6. **读取不再伪装为业务结论**：普通/游标分页加载时显示读取提示；成功后才呈现真实数量。所触及账号、库存、素材、页面、前置仓和餐饮列表读取失败不呈现零条结论。代码版本的密钥、出口IP、平台状态区分待读取与确实未配置。
7. **读取截止与写入恢复分离**：统一GET读取15秒截止覆盖响应正文，错误提供重新读取提示；CSRF启动读取也有截止。业务写请求没有新增自动中断或自动重试，原幂等/结果核查继续保留。401在解析正文前广播会话失效。
