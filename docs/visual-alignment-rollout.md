## 切片工程复核

1. **职责与契约**：视觉留在已有客户端业务域；订单待办事实由 fulfillment 读模型提供，售后数量规则由 aftersales 读辅助提供，customers 只限定本人并组装摘要。API 仅增加可选筛选和字段。
2. **数据库约束**：继续使用已有订单、发货、券与售后事实及原事务约束，没有迁移或新写入路径。
3. **并发与失败**：原修订、幂等、未保存保护、未知结果恢复保留；会员缺计数字段显示未知而非零；服务端读失败通过原错误/重试路径处理。
4. **规模**：数据库先过滤后分页，Exists 避免订单重复；会员计数单次聚合，列表小页/多单页查询数固定且不超过 7，不在客户端拉全量匹配。
5. **证据**：上表区分行为、组件、浏览器、真实隔离库、官方编译及模拟器；目标环境和真机未被这些证据替代。
6. **扩展位置**：新待办条件统一扩展 fulfillment/task_reads，售后事实扩展 aftersales/task_reads；客户端通过既有订单 API 消费，导航按路由元数据权限过滤。
7. **复用与例外**：共享视觉 tokens、Element Plus、现有经营统计、原生地区 picker、member/orders 呈现层；没有跨端组件框架、另一套 HTTP 或业务恢复控制器。样板的额外业务能力仍单独立项。
