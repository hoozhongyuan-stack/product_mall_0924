# 后台体验五项优先改造验收记录

日期：2026-10-10。分支：`codex/micro-pages-release`。

本轮完成本地代码改造、自动化回归和隔离环境浏览器验收，尚未提交、推送或部署至 UAT。第 4 项的微信平台与真机发布验收仍待完成。

## 改造结果

| 优先项 | 实施内容 | 验收状态 |
| --- | --- | --- |
| 库存数量口径 | 按基础单位分别汇总实物、预留和可用库存；同仓库同库存池去重；明确当前页口径，加载失败时不保留旧汇总 | 本地通过 |
| 优惠券生命周期 | 列表、详情和发券共用有效期判定；已结束显示原因并禁用发券；页面随时间更新，最终提交再次检查；保留原有请求恢复机制 | 本地通过 |
| 微页面编辑首屏 | 选中页面后收起列表，三栏编辑区前置；组件分为常用、内容、商品营销、布局辅助；390px 下使用预览、组件、设置切换 | 本地通过 |
| 微页面发布闭环 | 明确保存草稿→检查并预览→发布；检查并预览会先保存修改；检查结果须对应当前修订；最终发布再次核验；运行端不支持时提供说明及代码版本入口 | 后台流程通过；微信平台与真机未验收 |
| 工作台操作效率 | 六个有权限的常用入口前置；今日经营取服务端时区对应日期；范围统计、日报和完整入口折叠；日报倒序分页，保留原有导出口径 | 本地通过 |

库存混合单位样例通过单元与组件测试验证：480 件与 419 瓶分别展示，不合并为 899。浏览器隔离环境仅有件单位库存，因此浏览器截图不作为混合单位验证证据。未新增缺少数据来源的待办数量。

## 第 4 项后续发布验收

1. 固定小程序源码提交及目标 AppID，确认 UAT HTTPS 接口与合法域名；使用已有发布凭据与上传通道生成可追溯的上传记录。
2. 在开发者工具及真实设备检查 schema 1–4 页面：基础内容、商品、优惠券、热区、魔方、页面跳转、旧页面兼容及错误兜底。
3. 确认目标小程序代码实际承载新渲染能力后，由部署负责人更新与之对应的运行能力声明；不得仅修改声明来绕过发布检查。
4. 在目标环境检查并预览测试微页面，发布并从首页/其他微页面引用；在小程序读取已发布内容，记录修订号、跳转结果及回退验证。
5. 留存上传任务、体验版/正式版身份、设备和测试结果；以上证据齐备后才将第 4 项标记为端到端通过。

发布本轮后台改造后，还需在 UAT 重新验证实际权限、混合单位库存、已结束活动和微页面保存/预览。隔离环境结果不能替代部署后的验收。
