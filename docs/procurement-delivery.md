# 进货、首页与配送优化

本期依据已确认的 `docs/prototypes/procurement-delivery/` HTML 交互稿实施。金额均为分，后台以元输入。示例门槛仅用作新建表单初值，未保存不生效。

## 后台入口与规则

- 店铺 → 快递与包邮（`/shipping-rules`）：运费模板、规格重量、平台活动和服务端试算。
- 前置仓详情 → 配置配送规则：圆形／多边形服务区与排除区、优先级（较小优先）、时段、起送金额、经营包邮门槛、固定／距离计费。
- 餐饮店资料：与前置仓共用地图选点组件。地址变化后重新定位。
- 以上运费配置要求 `settlement.shipping.manage`；活动仓与围栏目标使用该权限下的最小仓信息读接口，不要求完整前置仓读取权限。

快递支持固定、按件和按重量计费；地区可逐级选择省、市、区县，可指定禁配地区。重量按规格当前销售单位配置，单位版本变化需重新配置。指定商品模板优先，其他商品使用默认模板；多模板订单逐组计算后合计。缺失规则／重量不会静默当零运费。

门槛金额 = 商品金额 − 优惠券优惠，不含运费，积分抵扣不改变门槛。先验证地址、围栏、时段和起送金额，随后计算运费与包邮。排除区优先于服务区；服务区按配置优先级选中，不以较便宜规则替代不满足条件的规则。

经营包邮由订单前置仓承担。满足时间、金额、交付方式及适用仓范围的平台活动包邮由平台承担，覆盖经营包邮；平台净收益可因补贴为负。不会既扣前置仓又扣平台。费用快照满足：

`配送成本 = 顾客运费 + 前置仓承担 + 平台承担`

顾客界面显示服务端运费与包邮来源；多模板仅部分包邮时显示“部分商品包邮”。实际提交重新验证报价、配置修订和资格，成交后冻结费用承担快照，改配置不改变已有订单。平台资助由平台净额扣减，经营包邮从仓收益扣减，客户已支付的运费不重复扣仓。

配置采用修订号并发检查。未知写入结果须重新读取并核对列表，恢复成功后关闭原编辑窗，防止重复创建。地图与行政区读取复用后台配置的高德服务；无密钥时显示可重试提示，不伪造地区或地图。

## 进货与首页

数量弹窗改为可滚动规格列表，44px 输入／加减控件和固定确认区，未配置价格的规格不可输入。0 表示不选择，数量范围 0–999。

选付款凭证会触发小程序页面隐藏；修复保留当前有效选图任务，返回后继续上传，卸载／退出／切换身份后丢弃回调。取消、权限、网络失败分别提示；只允许对有效原图片重试。上传成功不代表收款，凭证提交后进入平台核款状态。私有凭证继续鉴权，原请求重试保留相同业务请求键。

正常启动直接进入 `pages/home/home`，加载当前发布的首页微页面。就绪前显示中性骨架，不显示临时仓标题或另一套首页。刷新清除旧布局，迟到响应不能覆盖新页面。

## 编号与迁移

编号为业务类型 + 北京时间 `YYYYMMDDHHmmss` + 当日该类型六位序号。XS 普通销售、CY 餐饮销售、JH 进货、JF 积分兑换、SH 售后、TK 退款。并发分配由数据库原子递增；事务回滚不消费序号，超过每日上限拒绝创建。内部 UUID 与支付外部标识仍独立。

迁移给既有进货单和售后单按创建时间填充新编号；原销售／退款外部引用不重写。新增订单与报价费用快照不可变。既有配送半径／费仅在一次数据迁移中转换为规则，运行时统一使用新规则；新仓须明确配置配送范围。平台活动默认关闭，不将 HTML 示例活动自动投入经营。历史未冻结配送成本的订单不补造成本，未结算时保持待人工核对；已结算收入不重算。

## 验证边界

浏览器采用正式后台源码和隔离数据库验证保存、刷新回读及服务端试算；小程序浏览器稿由实际 WXML/WXSS/JS 编译渲染、合成回调验证数量／凭证／首页状态。浏览器适配不能替代微信真机的软键盘、相册授权与真实上传验收。UAT 部署会生成对应不可变小程序代码包；微信上传／体验版本切换和正式发布必须分别有实际平台结果。
