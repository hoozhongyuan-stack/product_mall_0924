# B2C 商城与前置仓协同系统

一套由平台统一运营的微信商城：顾客在小程序购物，前置仓负责本地配送与自提，平台总仓负责快递，餐饮联盟店通过餐桌码引入消费并按成交规则获得佣金。

系统包含 **PC 管理后台、微信原生小程序、Django API 与后台任务服务**。前置仓中心和餐饮联盟中心位于同一个小程序内，按会员授权显示入口，不需要另装商家 App。

## 能做什么

- **商城经营**：分类、商品与多规格、等级价、购物车、地址、下单、订单、售后、优惠券与积分。
- **店铺装修**：编辑并发布微页面，将某个已发布微页面设为首页；配置最多五项底部导航及独立的选中／未选中图标。
- **库存与前置仓**：多仓库存、基础单位换算与共享库存池、入出库和盘点、前置仓进货、店内销售授权、本地履约与账户。
- **餐饮联盟**：餐饮店与餐桌码、固定店铺消费、匹配服务前置仓、商品佣金、账户和提现申请审核。
- **配送与履约**：快递运费模板、本地配送电子围栏及门槛、费用承担快照、分批快递、按数量交付、自提凭证和虚拟权益核销。
- **运营与管理**：经营概览、私有导出、子账号、权限组、审计、小程序接入与开发版本上传任务。

支付、退款、物流轨迹、订阅消息和微信代码发布均有各自的配置与启用条件；存在页面或适配器不代表真实渠道已开通。具体边界见[产品介绍中的交付状态](docs/product-overview.md#交付状态与上线边界)。

## 系统结构

```text
PC 管理后台（Vue 3） ── HTTPS 同源 /api ──┐
                                        ├── Django API ── PostgreSQL
微信原生小程序 ─────── HTTPS /api ────────┘       │
                                                ├── 私有媒体／凭证／源码包／导出文件
                                                └── 后台维护、导出与代码上传任务
```

| 目录 | 用途 |
| --- | --- |
| `backend/` | Django 业务模块、数据库迁移、API 与管理命令 |
| `pc-admin/` | Vue 3、TypeScript、Vite、Element Plus 管理后台 |
| `mini-program/` | 微信原生 JS／WXML／WXSS 小程序 |
| `mini-ci-worker/` | 微信 `miniprogram-ci` 上传执行适配器 |
| `deploy/`、`scripts/`、`compose*.yaml` | Docker 镜像、部署闸门、升级、备份与隔离恢复 |
| `docs/` | 产品导览、接口契约、实施说明与验收证据 |
| `docs/prototypes/` | 产品交互稿；原型中的演示数据不代表线上业务数据 |

根目录 `compose.yaml` **只启动本地 PostgreSQL**。完整应用部署使用 `compose.production.yaml` 及 E5 脚本；不要把启动数据库当作已经部署了商城。[部署指南](docs/deployment.md)提供两种路径。
